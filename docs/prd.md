## 서비스 개요

- **서비스명:** CrossFit Beginner Mate
- **서비스 목적:** 크로스핏 와드(WOD) 정보를 입력하면, LLM API를 통해 초보자 눈높이에 맞춘 운동 설명(영어 운동명 풀이, 랩/세트 개념 설명 등), 팁, 주의사항, 그리고 쿨다운 스트레칭(유튜브 검색 링크 포함) 정보를 자동 생성하고 제공하는 웹 서비스.
- **타겟 사용자:** 크로스핏 입문자 (영어 운동명, 랩/세트 개념에 익숙하지 않은 사용자)
- **접근 권한 정책:**
  - 일반 사용자: 회원가입 및 로그인 없이 누구나 정보 뷰 페이지에 접근할 수 있습니다.
  - 관리자: 고정 비밀번호와 보안 세션을 이용해 인증 후 관리자 페이지에 접근할 수 있습니다.
- **타임존:** 대한민국(Asia/Seoul) 고정. 모든 날짜·시간 입력/표시는 KST 기준이며 별도 타임존 변환을 지원하지 않습니다.
- **디바이스 대응:** 모바일 반응형 UI를 필수로 지원합니다(관리자 페이지 포함). 데스크톱은 부가적으로 대응합니다.
- **MVP 범위:** 1차 개발은 관리자 기능(인증/세션 CRUD)과 와드 정보 출력(사용자 뷰)까지로 한정했습니다. LLM(Gemini) 연동은 MVP 완료 후 이어서 구현했으며, CI/CD와 실제 배포만 남아있습니다.

## 핵심 기능 요구사항

### 관리자 페이지

- **인증 기능 및 보안 보완**
  - 고정 관리자 비밀번호를 환경 변수로 안전하게 비교하여 검증합니다.
  - 로그인 실패 시도 횟수를 제한하는 **Rate Limiter를** 적용하여 연속 5회 실패 시 15분간 접속을 차단합니다.
    - **저장소:** 별도 인프라 없이 D1에 `login_attempts(ip, fail_count, blocked_until, updated_at)` 테이블을 두어 IP 기준으로 실패 횟수를 관리합니다. `blocked_until`이 현재보다 미래면 요청을 즉시 차단하고, 로그인 성공 시 해당 row를 초기화합니다.
  - 로그인 성공 시 **JWT 기반 세션 쿠키를** 발급하고 **HttpOnly**, **Secure**, **SameSite=Strict** 옵션을 지정합니다.
    - **알고리즘:** HS256(대칭키). 단일 고정 관리자만 존재하므로 비대칭키는 불필요합니다.
    - **Secret 관리:** Cloudflare Workers Secret `JWT_SECRET`으로 관리하며 코드에 하드코딩하지 않습니다.
    - **만료(exp):** 24시간. Refresh 토큰은 두지 않고, 만료되면 재로그인합니다.
    - **쿠키명:** `admin_session`. **Payload:** `{ role: "admin", iat, exp }` (개별 사용자 식별 불필요).
    - **검증:** 관리자 API/페이지 요청마다 미들웨어에서 서명·만료를 검증하고, 실패 시 401 반환 후 로그인 페이지로 리다이렉트합니다.

- **관리자 편집 UI**
  - 사용자 뷰 페이지에는 관리자 진입 링크를 노출하지 않습니다. 관리자는 `/admin` 경로로 직접 접근하며, 로그인되어 있지 않으면 로그인 페이지로 자동 리다이렉트됩니다.
  - **일반 사용자 페이지와 동일한 UI 골격을 재사용합니다:** 상단 날짜 제목 + 좌우 스크롤 날짜 스트립으로 날짜를 선택하고(캘린더 피커 없음), 해당 날짜의 세션을 **카드 목록**으로 표시합니다(클래스명 + 원본 와드 텍스트를 바로 노출 — 사용자 뷰와 동일). 관리자는 가이드 유무와 무관하게 항상 카드를 클릭해 액션에 접근할 수 있습니다.
  - 카드를 클릭하면 사용자 페이지와 동일한 **PC 모달 / 모바일 바텀시트**가 열려 (있는 경우) LLM 가이드 미리보기를 보여주고, 패널 하단에 관리자 전용 액션 버튼(**가이드 생성/재생성**, **수정**, **삭제**)을 배치합니다. 원본 와드 텍스트는 카드에 이미 노출되어 있으므로 패널에서 중복 표시하지 않습니다.
  - "+ 세션 추가" 버튼으로 새 세션을 추가합니다. 폼에는 날짜(현재 선택된 날짜로 자동 채움), 클래스 종류(드롭다운: CF Class / Strength Class / Weightlifting Class / 기타), 와드 텍스트를 입력합니다(시간 입력 없음).
  - 동일 날짜·동일 클래스 종류가 이미 존재하면 저장을 반려합니다.
  - 상세 패널의 "수정" 버튼을 누르면 기존 값이 채워진 동일 폼이 열리고, "삭제"는 확인 다이얼로그를 거칩니다. 세션을 수정해 날짜가 바뀌면 날짜 스트립도 새 날짜로 자동 이동합니다.

- **와드 등록 및 편집 (CRUD)**
  - **입력 단위:** 관리자는 날짜를 하나 선택한 뒤, 그 날짜에 진행되는 **클래스 종류 단위로** 와드를 작성합니다. 주간 일괄 붙여넣기는 지원하지 않고 일자별로 작성합니다.
  - **세션(클래스 종류) 구조:** 하루에 여러 타임이 운영되더라도 같은 클래스 종류(예: CF Class)로 진행되는 세션은 모두 동일한 와드를 수행하므로, 시간대는 데이터로 관리하지 않습니다. 다만 어떤 날은 CF Class와 Strength Class/Weightlifting Class가 번갈아 진행되며 이 경우 와드 내용이 서로 다르므로, **같은 날짜에 클래스 종류별로 세션을 여러 개 추가/수정/삭제**할 수 있어야 합니다(예: 같은 날 "CF Class" 세션 1개 + "Strength Class" 세션 1개).
  - **세션별 입력 항목:** 클래스 종류(CF Class / Strength Class / Weightlifting Class 등), 해당 클래스의 원본 와드 텍스트. (시작/종료 시간은 저장하지 않음 — 같은 클래스 종류의 모든 타임은 동일한 와드이므로 시간 구분이 불필요하다고 판단.)
  - **LLM 연동 및 구조화 출력 (구현 완료):** 관리자가 세션을 저장한 뒤, 대시보드에서 **"가이드 생성" 버튼을 눌러 수동으로 트리거**합니다(세션 저장 시 자동 호출 아님 — raw_wod를 여러 번 고치는 동안 불필요한 API 호출이 반복되는 것을 방지). 요청은 **동기 처리**로, 관리자는 응답을 기다리는 동안 버튼이 "생성 중..."으로 바뀌고 완료되면 목록이 즉시 갱신됩니다. 이미 `parsed_guide`가 있는 세션에 다시 요청하면 confirm 다이얼로그로 덮어쓰기 여부를 확인합니다.
    - **모델:** Google Gemini API(`gemini-3.1-flash-lite`), REST `generateContent` 엔드포인트를 `x-goog-api-key` 헤더로 호출(`src/llm.ts`). API 키는 Cloudflare Workers Secret `GEMINI_API_KEY`로 관리하며 로컬은 `.dev.vars`에 별도 보관(코드에 하드코딩 금지).
    - **구조화 출력:** Gemini의 `responseSchema`(OpenAPI 서브셋) + `responseMimeType: "application/json"`으로 출력 형태를 강제해 파싱 실패/필드 누락 위험을 줄입니다.
    - **프롬프트 설계:** 실제 더미 데이터(2026-08-06, 9-7-5 Clean & Jerk 와드)를 few-shot 예시로 프롬프트에 포함해 출력 톤·분량·스케일링 팁의 구체성을 고정합니다. `youtube_search_keyword`는 "스트레칭" 같은 범용 단어 조합을 피하고 부위명 중심의 2~3단어로 생성하도록 명시(검색 결과가 뭉개지는 문제 방지).
    - **엔드포인트:** `POST /api/admin/sessions/:id/guide` (인증 필요) — 성공 시 갱신된 세션 반환(200), 세션 없음(404), Gemini 호출/응답 검증 실패(502).
    - `class_type`(CF Class/Strength Class/Weightlifting Class)은 세션 테이블 컬럼으로 이미 존재하므로 LLM 출력에는 중복시키지 않고, 와드 자체의 형식과 콘텐츠만 담습니다.
    ```json
    {
      "workout_type": "AMRAP / For Time / EMOM / Interval / Strength / Weightlifting",
      "target_explanation": "오늘 운동 방식과 목표를 초보자 눈높이에서 설명",
      "warmup_movements": [
        { "name_en": "...", "name_kr": "...", "description": "...", "scaling_tip": "..." }
      ],
      "movements": [
        { "name_en": "...", "name_kr": "...", "description": "...", "scaling_tip": "..." }
      ],
      "key_tips": ["..."],
      "cooldown_stretches": [
        { "stretch_name": "...", "target_muscle": "...", "youtube_search_keyword": "..." }
      ]
    }
    ```
    - **`warmup_movements` (선택 필드):** 와드 원문에 "Core"처럼 본 운동 전에 진행하는 웜업/보조 파트가 별도로 있으면 그 동작들을 담습니다. "METCON"(또는 별도 표시 없는 본 운동) 파트는 항상 `movements`에 담깁니다. 웜업 파트가 없는 와드는 이 필드가 비거나 생략됩니다. (초기에는 "Core+METCON을 별도로 표현할 필요 없음"으로 결정했으나, 실제로 Core 파트가 통째로 누락되는 문제가 발견되어 이 필드를 추가하는 것으로 정정했습니다.)
    - **유튜브 관련 설계 결정 (최종):** 특정 영상을 골라 iframe에 임베드하지 않습니다. 검토 과정에서 `listType=search` 검색 기반 embed는 YouTube가 지원을 중단해 재생되지 않음을 확인했고, 대안으로 실존 `video_id`를 직접 임베드하는 방식도 검토했으나 YouTube Data API 연동(키·할당량), `videoEmbeddable` 필터링, LLM의 video_id 환각 위험까지 감당할 이유가 없다고 판단해 **채택하지 않았습니다.**
      - 대신 LLM(또는 관리자)이 `youtube_search_keyword`만 생성하고, 사용자 뷰에서는 `https://www.youtube.com/results?search_query=<keyword>`로 이동하는 **"유튜브에서 검색해보기" 링크**(새 탭)만 제공합니다.
      - 이 방식은 별도 API 연동이 필요 없고, 재생 불가/환각 위험이 원천적으로 없으며, 유튜브 자체의 검색 품질을 그대로 활용합니다. LLM 연동 여부와 무관하게 지금 바로 동작합니다(실제로 더미 데이터로 검증 완료).
  - **저장 및 관리:** 날짜 및 세션별 데이터를 데이터베이스에 저장하며 관리자가 세션 단위로 내용을 수정하거나 삭제할 수 있는 UI를 제공합니다.

### 정보 뷰 페이지 (사용자용)

- **날짜 제목 + 날짜 스트립**
  - 화면 상단에 선택한 날짜를 크게 표시하는 제목(`N월 N일 N요일`)을 중앙에 배치합니다.
  - 그 아래 좌우로 스크롤 가능한 날짜 스트립(요일+숫자)을 배치합니다. 별도의 이전/다음 주 버튼이나 상단 고정 네비게이션 바는 두지 않고, 스크롤만으로 다른 날짜(기본 전후 14일 범위)로 이동합니다.
  - 날짜 선택 시 해당 일자 와드 정보를 즉시 렌더링합니다.

- **콘텐츠 영역 (Main Content Area)**
  - 선택한 날짜에 등록된 세션(클래스 종류별)을 **카드 목록**으로 표시하며, 각 카드에는 클래스명과 관리자가 입력한 **원본 와드 텍스트를 곧바로** 노출합니다(클릭 없이 바로 확인). 시간 정보는 저장하지 않으므로 표시하지 않습니다.
  - `parsed_guide`(LLM 출력)가 있는 카드만 클릭 가능하며(우측 화살표로 표시), 클릭하면 **PC는 중앙 모달, 모바일은 하단에서 올라오는 바텀시트**로 LLM이 생성한 추가 정보만 표시합니다: 오늘의 목표(운동 형식+설명), (있는 경우) 웜업(Core) 동작 설명, 본 운동 동작 설명(영문/국문 명칭, 설명, 스케일링 팁), 운동 팁, 쿨다운 스트레칭(부위명 + "유튜브에서 검색해보기" 링크). 원본 와드 텍스트는 이미 카드에 노출되어 있으므로 상세 화면에서 중복 표시하지 않습니다.
  - `parsed_guide`가 없는 카드(LLM 연동 전 또는 아직 생성되지 않은 세션)는 더 볼 내용이 없으므로 클릭 동작을 두지 않습니다(화살표 없음).
  - 날짜를 변경하면 목록 전체가 즉시 교체되지 않고 **좌우 슬라이드 전환**(이후 날짜는 좌→ 진행 방향, 이전 날짜는 반대)으로 자연스럽게 전환됩니다.

- **데이터 미존재 일자 UI 처리**
  - 선택한 날짜에 등록된 와드가 없는 경우 빈 화면 대신 안내 카드를 표시합니다.
  - 안내 문구 예시: `"선택하신 날짜에는 등록된 와드가 없습니다."`
  - 별도의 날짜 이동 버튼은 안내 카드에 중복 배치하지 않습니다 — 상단 날짜 스트립이 항상 노출되어 있으므로 그것으로 다른 날짜를 선택하면 됩니다(불필요한 정보 중복 제거).

## 유저 플로우

### 관리자 플로우

1. 관리자 로그인 페이지 접속 후 고정 비밀번호 입력.
2. 비밀번호 검증 및 **Rate Limiter** 확인 후 **JWT 세션 쿠키** 발급 및 관리자 페이지 진입.
3. 날짜를 하나 선택.
4. 해당 날짜에 세션을 추가: 클래스 종류(CF Class / Strength Class / Weightlifting Class 등), 와드 텍스트 입력.
5. 같은 날짜에 클래스 종류가 여러 개면(예: CF Class와 Strength Class가 번갈아 진행) 3~4를 반복해 세션을 추가.
6. 저장 후 필요 시 특정 세션을 개별적으로 수정하거나 삭제.

### 일반 사용자 플로우

1. 웹 서비스 메인 접속 (로그인 없음).
2. 날짜 스트립에서 날짜 선택(좌우 스크롤로 탐색, 전후 14일 범위).
3. 저장 데이터 존재 여부 확인:
   - 데이터 존재하는 경우: 해당 날짜의 세션 요약 목록(클래스 종류)을 확인하고, 클릭해 상세(모달/바텀시트)에서 원본 와드 및 LLM 가이드(있는 경우)를 확인.
   - 데이터 미존재 경우: 와드 미등록 안내 카드 확인 후 날짜 스트립에서 다른 날짜 선택.

## 데이터 구조 설계 (Schema)

### WOD 세션 데이터베이스 테이블 (`wod_sessions`)

같은 날짜에 클래스 종류가 여러 개 진행될 수 있으므로(예: CF Class와 Strength Class가 번갈아 진행), `date` 단독이 아니라 **날짜 + 클래스 종류 단위**로 레코드를 저장합니다. 같은 클래스 종류로 진행되는 여러 타임은 항상 동일한 와드이므로 시작/종료 시간은 저장하지 않습니다.

- `id`: 고유 식별자 (Text / UUID, Primary Key)
- `date`: 운동 날짜 (YYYY-MM-DD)
- `class_type`: 클래스 종류 (`CF Class` / `Strength Class` / `Weightlifting Class` 등 문자열)
- `raw_wod`: 관리자가 입력한 해당 클래스의 원본 와드 텍스트 (Text)
- `parsed_guide`: LLM(Gemini)이 생성한 구조화 데이터 (JSONB, Nullable) — 관리자가 "가이드 생성"을 실행하기 전까지는 `NULL`
- `created_at`: 데이터 생성일시 (DateTime)
- `updated_at`: 데이터 수정일시 (DateTime)

**Index:** `(date, class_type)`에 Unique Index를 두어 같은 날 같은 클래스 종류의 세션이 중복 생성되지 않도록 합니다. 하루에 여러 클래스 종류가 존재하는 것은 정상 상태이므로 `date` 자체는 Unique로 두지 않습니다.

> LLM 연동(Gemini API, `src/llm.ts`)과 프롬프트 설계는 완료되었습니다. 세부 사항은 위 "와드 등록 및 편집" 절을 참고하세요.

> **타입 표기 관련 각주:** D1(SQLite 기반)에는 JSONB/DateTime 전용 타입이 없습니다. 위 컬럼 표기(JSONB, DateTime)는 개념적 구분이며, 실제 D1 컬럼 타입은 `parsed_guide`를 포함해 모두 `TEXT`(JSON 문자열/ISO 날짜 문자열)로 저장합니다.

## 기술 스택

- **API:** **Hono**(TypeScript) 기반 Cloudflare Pages Functions로 라우팅, D1 접근, JWT 인증, Rate Limiter를 구현합니다. Hono는 API 표면이 작고 문서가 단순해 유지보수·AI 코딩 부담이 적고, Cloudflare Pages Functions와 공식적으로 지원됩니다.
- **프론트엔드:** 별도 SPA 프레임워크(React/Next.js 등) 없이 **정적 HTML/CSS + Vanilla TypeScript**로 구성합니다. 화면 수가 적고(관리자 페이지, 사용자 뷰 페이지) 상태 관리가 단순해 프레임워크 오버헤드보다 단순함의 이득이 큽니다.
- **배포:** 기존에 정의한 Cloudflare Pages + D1 아키텍처를 그대로 유지하며, 이번 결정은 그 위에 올라가는 프레임워크 레이어만 확정한 것입니다.

## Cloudflare 배포 및 캐싱 전략

- **배포 아티텍처**
  - 프론트엔드: **Cloudflare Pages를** 사용하여 글로벌 CDN으로 고속 정적 렌더링을 제공합니다.
  - API: Cloudflare **Pages Functions**(Hono 마운트, `functions/api/[[route]].ts`)로 별도 Workers 프로젝트 없이 Pages 하나로 프론트엔드와 API를 함께 배포합니다.
  - 데이터베이스: **Cloudflare D1** 서버리스 DB를 Pages Functions에 바인딩합니다.

- **캐싱 전략 (Cache-Control & Cache Purge)**
  - 사용자 뷰 API 응답에 `Cache-Control: public, max-age=3600, s-maxage=86400` 헤더를 설정합니다.
  - 데이터가 변경되지 않는 한 Edge 캐시에서 즉시 빠른 응답을 반환합니다.
  - **캐시 무효화 범위 세분화:** 관리자가 세션을 추가/수정/삭제할 때 전체 캐시를 삭제하지 않고, 해당 날짜의 사용자 뷰 API URL(`GET /api/wods?date=YYYY-MM-DD` 등 세션 목록 조회 URL)만 **Purge by URL로 정밀 타겟팅**하여 무효화합니다. 다른 날짜의 캐시는 영향받지 않습니다.
  - URL Purge가 정확히 매칭되도록 날짜 쿼리 파라미터 형식을 프론트/API 전역에서 통일합니다(`?date=YYYY-MM-DD` 고정).
  - 향후 "주간 데이터 존재 여부" 등 집계용 API가 추가되면 해당 API도 날짜 변경 시 함께 Purge 대상에 포함합니다.
